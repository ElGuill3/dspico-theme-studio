# Proposal: DSpico Theme Studio MVP

## Intent

Deliver an offline Electron GUI for Material-theme authors. Replace manual JSON editing and uncertain visual checks with a complete, recoverable journey, honest previews, source-backed diagnostics, and reproducible launcher-ready exports—without AI.

## Scope

### In Scope
- Create a Material project; edit metadata, tokens, screen/mode overrides, and launch transitions; save, reopen, diagnose, preview, undo, redo, and export.
- Show interactive 256×192 physical top/bottom previews with representative content and explicit fidelity labels.
- Produce a ready-to-copy folder and byte-deterministic ZIP containing `theme.json` and an ordered compatibility/checksum/warning/credit/license report.

### Out of Scope
- Custom canvas/conversion, raw markup, image/background or audio tooling, CLI/MCP/agents, embedded AI, direct SD installation, cloud/collaboration, and DS pixel parity.

## Capabilities

### New Capabilities
- `offline-material-authoring`: Versioned project persistence, semantic editing, diagnostics, and undo/redo.
- `material-dual-screen-preview`: Honest top/bottom Material visualization.
- `dspico-compatibility-validation`: Target-profile validation backed by launcher sources and fixtures.
- `deterministic-theme-export`: Stable folder, ZIP, hashes, and report output.

### Modified Capabilities
None.

## Product Boundaries and Approach

- `formatVersion: 1` separates projects from exports: `project.json` references tokens, ordered physical screen/mode recipes, assets, and a target profile. Unknown newer formats are never overwritten.
- Completed semantic edits are versioned atomic operations; UI state is excluded. Warning acknowledgments persist by diagnostic fingerprint. Editing after undo clears redo; snapshot retention is bounded.
- A deterministic shared core owns models, migrations, operations, diagnostics, and compilation. Electron is the sandboxed GUI/filesystem shell; future peer adapters remain optional.
- Preview accuracy covers only launcher-vector-backed dimensions, bounds, inheritance, wrapping, and Material colors. Validation and generated bytes—not Chromium resemblance—determine export truth.

## Dependencies and Risks

- Before compatibility specs, pin `dspico-launcher-v1` to an exact launcher release/commit and source-backed fixtures. Choose desktop OS/signing targets before packaging design.
- Main risks are launcher drift, unverified Material-color parity, ZIP metadata nondeterminism, and persistence corruption. Invalid/empty values block export; warnings require acknowledgment; suggestions remain informational.

## Rollback and Recovery

Atomic saves and staged exports preserve the prior valid state. After interruption, reopen the last committed head, report recoverable orphaned data, discard failed staging, and retain migration/reader support.

## Success Criteria

- [ ] A user completes the full journey offline without AI or manual file editing.
- [ ] Save/reopen and operation replay preserve canonical state; undo/redo behaves across branching edits.
- [ ] Errors block export, acknowledged warnings do not, and previews never imply DS pixel parity.
- [ ] Identical project, compiler, and target-profile versions produce identical files, report order, hashes, and ZIP bytes.
